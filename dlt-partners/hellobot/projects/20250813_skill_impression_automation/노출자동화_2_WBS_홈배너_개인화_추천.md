# 홈 배너 개인화 추천 시스템 WBS (Work Breakdown Structure)

## 프로젝트 개요

**목표**: HelloBot 홈 배너 지면에 사용자 맞춤형 콘텐츠 추천 알고리즘을 적용하고 A/B 테스트를 수행할 수 있는 환경 구축

**기간**: 2025년 1분기 ~ 2분기 (예상)

**핵심 성과 지표**:

- 구매자 ARPPU 증대
- 사용자의 일 평균 진입 스킬수 증가
- 1주/1개월 LTV 개선

---

## 1. 1차 구현 목표 (MVP)

### 목표: 홈 배너 지면 A/B 테스트 환경 구축 및 기본 알고리즘 2~3개 구현

### 1.1 데이터 인프라 구축

#### 1.1.1 데이터 수집 및 저장

- [ ] BigQuery 데이터 마트 설계 및 구축 (5일)
  - [ ] 사용자 행동 데이터 테이블 설계
  - [ ] 스킬 메타데이터 테이블 설계
  - [ ] 사용자 세그먼트 테이블 설계
  - [ ] ETL 파이프라인 구축

#### 1.1.2 사용자 정보 구조화 (3일)

- [ ] 사용자 프로필 데이터 구조 정의
  - [ ] 기본 정보 (성별, 연령대, 가입일)
  - [ ] 구매 이력 정보 (구매 스킬, 구매 금액, 구매 주기)
  - [ ] 행동 패턴 정보 (조회 스킬, 진입 스킬, 체류 시간)

#### 1.1.3 스킬 정보 구조화 (2일)

- [ ] 스킬 메타데이터 구조 정의
  - [ ] 기본 정보 (스킬 ID, 카테고리, 가격)
  - [ ] 콘텐츠 속성 (주제, 타입, 키워드)
  - [ ] 성과 지표 (구매율, 조회수, 매출)

### 1.2 추천 알고리즘 개발

#### 1.2.1 기본 알고리즘 (Default) 구현 (3일)

- [ ] 신규/콜드 스타트 사용자용 기본 추천 로직
  - [ ] 최근 7일 베스트셀러 기반
  - [ ] 전체 사용자 평균 구매율 높은 스킬
  - [ ] 운영자 큐레이션 스킬 포함

#### 1.2.2 인기도 기반 알고리즘 구현 (3일)

- [ ] 시간대별 인기 스킬 추천
  - [ ] 최근 24시간 클릭률 기반
  - [ ] 최근 3일 구매 전환율 기반
  - [ ] 카테고리별 가중치 적용

#### 1.2.3 간단한 협업 필터링 알고리즘 구현 (4일)

- [ ] 사용자 구매 이력 기반 추천
  - [ ] 유사 사용자 그룹 정의
  - [ ] 아이템-아이템 유사도 계산
  - [ ] 이미 구매한 스킬 필터링

### 1.3 백엔드 API 개발

#### 1.3.1 추천 API 서버 구축 (5일)

- [ ] FastAPI 기반 서버 설정
- [ ] 추천 엔드포인트 개발
  - [ ] GET /recommendations/home-banner
  - [ ] 사용자 ID 기반 개인화 응답
  - [ ] 알고리즘 버전 파라미터 지원

#### 1.3.2 캐싱 및 성능 최적화 (3일)

- [ ] Redis 캐시 레이어 구현
  - [ ] 사용자별 추천 결과 캐싱
  - [ ] TTL 설정 (1시간)
- [ ] 응답 시간 100ms 이내 달성

### 1.4 A/B 테스트 시스템

#### 1.4.1 사용자 그룹 분할 (2일)

- [ ] 사용자 그룹 할당 로직 구현
  - [ ] 해시 기반 균등 분할
  - [ ] 컨트롤 그룹(기존) / 테스트 그룹 A / 테스트 그룹 B

#### 1.4.2 실험 설정 관리 (3일)

- [ ] 실험 설정 관리 시스템
  - [ ] 실험 ID, 시작/종료 날짜
  - [ ] 그룹별 알고리즘 매핑
  - [ ] 실험 비율 설정 (예: 33%/33%/34%)

#### 1.4.3 이벤트 추적 (3일)

- [ ] 사용자 행동 이벤트 로깅
  - [ ] 노출 이벤트 (impression)
  - [ ] 클릭 이벤트 (click)
  - [ ] 구매 이벤트 (purchase)
  - [ ] 실험 그룹 정보 포함

### 1.5 모니터링 및 대시보드

#### 1.5.1 실시간 모니터링 (3일)

- [ ] 시스템 헬스 체크
  - [ ] API 응답 시간 모니터링
  - [ ] 에러율 추적
  - [ ] 캐시 히트율 모니터링

#### 1.5.2 A/B 테스트 대시보드 (4일)

- [ ] Looker/Tableau 대시보드 구축
  - [ ] 그룹별 핵심 지표 비교
    - [ ] CTR (Click-Through Rate)
    - [ ] CVR (Conversion Rate)
    - [ ] ARPPU
  - [ ] 통계적 유의성 검정 결과
  - [ ] 일별 추세 차트

### 1.6 안정성 및 폴백

#### 1.6.1 폴백 메커니즘 (2일)

- [ ] 추천 시스템 장애 시 기본 노출 로직
- [ ] 캐시 미스 시 Default 알고리즘 적용
- [ ] Circuit Breaker 패턴 구현

#### 1.6.2 알림 시스템 (1일)

- [ ] Slack 알림 설정
  - [ ] 시스템 장애 알림
  - [ ] 성능 저하 알림
  - [ ] 실험 종료 알림

#### 2.1.1 딥러닝 기반 추천 모델 (10일)

  - [ ] 사용자/아이템 임베딩 학습
  - [ ] Two-Tower 모델 구현
  - [ ] 모델 서빙 인프라 구축

## 3. 예상 일정

### 1차 구현 (MVP)

- **총 소요 기간**: 약 6-7주
- **개발 인력**: 백엔드 2명, 데이터 엔지니어 1명, 데이터 분석가 1명

### 2차 구현 (확장)

- **총 소요 기간**: 약 8-10주
- **개발 인력**: 백엔드 2명, ML 엔지니어 1명, 데이터 엔지니어 1명

---

## 4. 리스크 및 대응 방안

### 4.1 기술적 리스크

- **리스크**: 응답 시간 지연 (목표: 100ms 이내)
- **대응**: 사전 계산 및 캐싱 전략, 비동기 처리

### 4.2 비즈니스 리스크

- **리스크**: 매출 하락 가능성
- **대응**: 가드레일 지표 설정, 즉시 롤백 가능한 구조

### 4.3 데이터 리스크

- **리스크**: 콜드 스타트 문제
- **대응**: 하이브리드 접근 (규칙 기반 + ML)

---

## 5. 성공 기준

### 1차 구현 성공 기준

- [ ] 홈 배너 API 응답 시간 < 100ms
- [ ] A/B 테스트 3개 그룹 동시 운영 가능
- [ ] 실시간 지표 모니터링 대시보드 구축
- [ ] 시스템 가용성 99.9% 이상

### 2차 구현 성공 기준

- [ ] 구매자 ARPPU 10% 이상 증가
- [ ] 사용자 일 평균 진입 스킬수 20% 증가
- [ ] 1주 LTV 15% 개선
- [ ] 노출 다양성 지표 개선 (상위 20% 스킬 노출 비중 < 80%)
