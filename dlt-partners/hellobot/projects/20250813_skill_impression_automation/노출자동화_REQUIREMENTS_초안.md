# 목표

- 지속적으로 노출 알고리즘을 개발/적용/테스트하여 최적점을 찾아간다.
- 최적의 노출 알고리즘을 찾아 사용자에 맞는 콘텐츠 노출 비중을 늘리고(클릭한 콘텐츠 수), 사용자 1주일 LTV를 높인다.

# 1단계 목표: A/B 테스트 환경 구축

- 현재 단일 구성만 할 수 있는 홈 화면 운영
- 사용자별로 노출 알고리즘을 설정하여, 다른 콘텐츠가 노출 될 수 있도록 하고 싶다.
- 노출 알고리즘은 평상시 1개로 운영되고, 새로운 노출 알고리즘을 테스트 할 경우 동시에 여러개의 노출 알고리즘이 사용자 그룹별로 적용된다.
  - 전체 사용자는 기존 설정된(default) 노출 알고리즘을 적용받고, 일부 사용자 그룹이 새로운 노출 알고리즘을 적용 받는다.
  - 일부 사용자 그룹은 규칙을 정하여 구분하거나 랜덤하게 설정할 수 있다.
  - 사용자별 설정된 사용자 그룹의 기호가 사용자에게 부여되어있다.
- 설정된 사용자의 그룹은 사용자 별로 저장되거나, 사용자의 이벤트에 기록되어 향후 구분하여 데이터를 분석할 수 있다.

- 요구사항

  - 노출 알고리즘은 계속 바꾸고 적용해 볼 수 있다.
    - 최초 알고리즘은 사주 & 이미 본 스킬 제외?
  - 노출 알고리즘을 여러개 구성할 수 있고, 사용자별로 구분하여 노출 알고리즘을 적용할 수 있다.
  - 노출 알고리즘은 사용자 그룹 단위로 적용되며, 사용자는 특정 그룹에 속하게 된다. 한 명의 사용자에게는 같은 노출 알고리즘이 적용된다.
  - 새로운 노출 알고리즘은 기존 알고리즘과 병렬 노출되고, 각각을 A/B 세그먼트로 구분하여 데이터를 확인할 수 있다.

- 개인화 정보 = 사용자의 성향, 세그먼트를 분류할 수 있는 사용자의 개인 정보

# 서버 입장에서 어떻게 처리해야 할까?

- 현재 방식
  - 운영자가 수동으로 노출 스킬을 선정하여 세팅하고, 헬로우봇 API 서버에서 전담 처리
  - 스튜디오에서 홈배너의 스킬 목록 세트를 설정하면, 설정 되어있는 대로 + 미노출 스킬 같은 안되는 것 제외하고 그대로 사용자에게 노출
  - (노출될 스킬은 딱 설정 시점에 필요한 정보들을 입력해 둔다)
- 변경될 방식
  - 운영자가 노출 대상이 되는 스킬들을 정하고, 대상 스킬들은 노출에 필요한 정보들이 미리 다 입력이 되어있어야 한다.
  - 서버는 사용자 정보(user_seq)와 플랫폼 정보(App, Web)를 (추천 엔진)에 전달하며 스킬 목록을 요청한다.
  - (추천 엔진)은 사용자 정보를 조회한 후 해당 사용자의 상태에 맞는 스킬 목록을 뽑는다.
    - 신규인지 기존인지 등은 여기에서 전부 고려
  - 서버는 (추천 엔진)에서 온 스킬 목록(fixed_menu_seq list)을 기반으로, 노출에 필요한 정보를 DB에서 가져와 클라이언트에 순서와 함께 제공
- 성능 이슈
  - 기존은 사용자 요청이 오면 DB 조회 후 바로 Return
  - 변경안은 사용자 요청이 오면 추천 엔진 요청(Network 지연) + DB 조회 후 Return
  - 추천 엔진 요청시 거의 즉각적으로 결과를 받을 수 있는 구조 수립 필요
    - 사용자 요청시엔 사용자에게 제공해야 할 결과가 결정되어있어야 한다. (요청 왔을 때 계산하고 있지 않도록하기)
- 추천 엔진이 고장나면 어떻게 되나?
  - Default가 있어야 함. 이건 어디서 어떻게 관리?

- 입력값
  - 사용자 정보
  - 노출 지면
- 참조값 - (여기를 어떻게 만들지가 관건)
  - 사용자 고정/변동 정보
  - 사용자가 사용한 이력 통계 정보
  - 스킬 통계 정보
- 결과값
  - 노출 지면에 노출할 order/index가 명시된 스킬의 seq list
