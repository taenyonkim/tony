# 스킬 노출 자동화 시스템 요구사항 정리

## 1. 프로젝트 개요

### 1.1 목표

- **장기 목표**: 지속적인 노출 알고리즘 개발/적용/테스트를 통한 최적화

  - 사용자별 맞춤 콘텐츠 노출 비중 증대 (클릭 콘텐츠 수 증가)
  - 사용자별 조회, 진입 스킬수를 높이고, 이를 바탕으로 1주일 LTV 향상

- **1단계 목표**: 노출 알고리즘을 설정하여 적용할 수 있는 구조 구축
  - 현재 단일 구성의 홈 화면 → 사용자별 맞춤형 노출 알고리즘 적용
  - 다중 알고리즘 동시 운영 및 테스트 가능한 환경 구축
- **2단계 목표**: A/B 테스트 환경 구축
  - 현재 단일 구성의 홈 화면 → 사용자별 맞춤형 노출 알고리즘 적용
  - 다중 알고리즘 동시 운영 및 테스트 가능한 환경 구축
  - 알고리즘별로 결과를 모니터링할 수 있는 환경 구축

## 2. 시스템 요구사항

### 2.1 A/B 테스트 기능 요구사항

#### 2.1.1 노출 알고리즘 관리

- ✅ 노출 알고리즘의 유연한 변경 및 적용
- ✅ 다중 알고리즘 동시 구성 및 운영
- ✅ 사용자 그룹별 차별화된 알고리즘 적용
- ✅ 병렬 테스트 환경 지원 (기존 알고리즘 vs 신규 알고리즘)

#### 2.1.2 사용자 그룹 관리

- ✅ 사용자 그룹 단위 알고리즘 적용
- ✅ 규칙 기반 또는 랜덤 그룹 할당
- ✅ 사용자별 그룹 식별자 부여 및 저장
- ✅ 이벤트 로그를 통한 그룹별 데이터 분석 지원

#### 2.1.3 A/B 테스트 솔루션 옵션

- Firebase Remote Config / A/B Testing
- GrowthBook Self Hosted Solution

## 3. 데이터 수집 및 처리

### 3.1 사용자 정보 수집

#### 3.1.1 수집 대상 정보

- **개인화 정보**: 사용자 성향, 세그먼트 분류를 위한 개인 정보
- **행동 데이터**: 스킬 조회, 구매 등의 액션 데이터

#### 3.1.2 데이터 처리 방식

- **실시간 처리**

  - 사용자 구매 이력
  - 즉시 반영이 필요한 정보

- **배치 처리 (일 단위)**
  - 사용자 성향 분석
  - 세그먼트 분류
  - 복합 정보 기반 도출 데이터

### 3.2 사용자 정보 활용

- 스킬 노출 시점에 개인화 정보 실시간 조회
- 노출 지면별 차별화된 알고리즘 설정
- Default 설정 제공 (신규 사용자 대응)

## 4. 노출 알고리즘 구성 요소

### 4.1 스킬 정보 분류

#### 4.1.1 고정 정보

- **콘텐츠 분류**
  - 타입: 사주, 타로
  - 주제: 솔로, 연애, 궁합, 결혼, 재물, 성공, 신년운세 등
- **메타 정보**
  - 출시일
  - 시즈널 특성 (시즈널/스테디)

#### 4.1.2 변동 정보

- **매출 지표**
  - 총 매출
  - 플랫폼별 매출 (앱/웹)
  - 최근 매출 추이
  - 인당 매출 (ARPU)
- **트렌드 지표**
  - 주제별 매출 강도 (시즌별)
  - 플랫폼별 유입 활성도

### 4.2 노출 스킬 선정 로직

#### 4.2.1 기본 로직 (신규 사용자)

- **매출 기반 지표**
  - 총 매출 기준
  - 플랫폼별 매출 기준
  - 최근 매출 추이
  - 인당 매출 (ARPU)
- **콘텐츠 속성**
  - 시기적 특성 (시즈널/스테디)
  - 출시일 (신규 스킬 우대)
  - 콘텐츠 주제별 가중치
- **운영 정책**
  - 운영자 지정 Weight (1~10)

#### 4.2.2 실시간 정보 기반

- 노출당 구매 전환율

#### 4.2.3 사용자 이력 기반

- **사용자 상태 정보**

  - 연애 상태: 솔로, 연애중, 결혼준비, 결혼중, 이별/재회 등
  - 커리어: 학생, 취업준비, 직장인, 퇴사/이직 등
  - 생활: 이사 준비 등

- **구매 이력 분석**
  - 이미 구매한 스킬 목록
  - 선호 콘텐츠 타입 (사주/타로)
  - 선호 콘텐츠 주제
  - 일평균 구매 금액
  - 건당 평균 구매 금액
  - 평균 구매 빈도

## 5. 노출 지면별 전략

### 5.1 지면 분류 및 특성

#### 5.1.1 발견/추천 지면

- **홈배너**

  - 위치: 1~5번, 19, 20번 슬롯
  - 특성: 메인 추천 콘텐츠 노출

- **섹션**
  - 사용자 관심사 기반 섹션 순서 조정
  - 섹션 구성에 따른 맞춤형 노출

#### 5.1.2 탐색 지면

- **카테고리**

  - 사용자 자발적 탐색 공간
  - 최소한의 커스터마이징 적용
  - 사용자 특성 정보 수집 포인트

- **검색**
  - 능동적 정보 탐색 공간
  - 검색 행동 데이터 수집

## 6. 시스템 아키텍처

### 6.1 현재 방식

- 운영자 수동 노출 스킬 선정
- 헬로우봇 API 서버 전담 처리
- 스튜디오 설정 기반 직접 노출

### 6.2 개선 방식

#### 6.2.1 처리 흐름

1. 운영자가 노출 대상 스킬 풀 설정
2. 서버가 추천 엔진에 사용자 정보 전달
   - user_seq
   - 플랫폼 정보 (App/Web)
3. 추천 엔진이 맞춤형 스킬 목록 생성
4. 서버가 추천 엔진에서 받은 스킬의 부가 정보 조회 후 클라이언트 전달

#### 6.2.2 추천 엔진 요구사항

- **입력값**

  - 사용자 정보
  - 노출 지면 정보

- **참조 데이터**

  - 사용자 고정/변동 정보
  - 사용자 이력 통계
  - 스킬 통계 정보

- **출력값**
  - 순서가 지정된 스킬 목록 (fixed_menu_seq list)

### 6.3 성능 및 안정성

#### 6.3.1 성능 요구사항

- 추천 엔진 응답 시간 최소화 (즉시 응답)
- 사전 계산된 결과 제공 (실시간 계산 최소화)
- Network 지연 최적화

#### 6.3.2 안정성 요구사항

- Failover 전략: Default 노출 설정 유지
- 추천 엔진 장애 시 기본값 제공 체계

## 7. 노출 스킬 선정 프로세스

### 7.1 선정 단계

#### 7.1.1 전처리

- 전체 스킬 세트 정의
- 스킬 간 우선순위 설정
- 미노출 스킬 필터링

#### 7.1.2 기본 세트 선정

- ARPU 기반 우선순위 계산
  - ARPU = 구매 전환율 × 인당 구매 횟수 × 건당 구매 금액
- 콘텐츠 타입별 차별화 (사주/타로)

#### 7.1.3 운영자 조정

- 특정 스킬 우선순위 부여
- 기간 한정 프로모션 반영

## 8. 구현 우선순위

### Phase 1: 기본 인프라 구축

1. A/B 테스트 프레임워크 선정 및 구축
2. 사용자 그룹 관리 시스템 구현
3. 기본 노출 알고리즘 구현

### Phase 2: 데이터 수집 및 분석

1. 사용자 행동 데이터 수집 체계 구축
2. 실시간/배치 처리 파이프라인 구현
3. 분석 대시보드 개발

### Phase 3: 개인화 고도화

1. 사용자 이력 기반 알고리즘 개발
2. 지면별 맞춤형 알고리즘 적용
3. 성능 최적화

### Phase 4: 운영 및 확장

1. 운영자 관리 도구 개발
2. 알고리즘 성과 모니터링 체계 구축
3. 지속적인 알고리즘 개선

## 9. 성공 지표 (KPI)

- **사용자 참여도**

  - 클릭한 콘텐츠 수 증가율
  - 노출 대비 클릭률 (CTR)

- **비즈니스 성과**

  - 1주일 LTV 향상률
  - 구매 전환율
  - ARPU 증가율

- **시스템 성능**
  - 추천 엔진 응답 시간
  - 시스템 가용성
  - A/B 테스트 실행 속도
