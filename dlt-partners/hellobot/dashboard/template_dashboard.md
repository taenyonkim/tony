# 대시보드 설계 템플릿

## 1단계: 목표 및 범위 정의 (Defining the Goal & Scope) 🎯

가장 먼저 대시보드의 핵심 목표를 명확히 해야 합니다. 이 대시보드를 통해 사용자가 무엇을 알게 되고, 어떤 행동을 하길 기대하는지를 구체적으로 정의하는 단계입니다.

#### 핵심 질문:

1. 이 대시보드는 어떤 문제를 해결하기 위해 필요한가? (예: 실시간 서버 장애 감지, 마케팅 캠페인 성과 추적, 재고 부족 경고)
2. 사용자가 이 대시보드를 보고 어떤 의사결정을 내리게 되는가?
3. 모니터링의 주기는 실시간인가, 일간/주간인가?

- 팁: 목표를 한두 문장으로 명확하게 정의하고 시작하는 것이 좋습니다.
  - 예: "실시간으로 유입되는 사용자 트래픽과 전환율을 모니터링하여, 주요 이탈 지점을 신속하게 파악하고 대응한다."

## 2단계: 사용자 분석 및 페르소나 설정 (Analyzing the User) 🧑‍💻

대시보드를 사용할 사용자가 누구인지 정의하고 그들의 니즈를 파악합니다. 사용자의 데이터 이해 수준, 역할, 관심사에 따라 대시보드의 구성과 깊이가 달라집니다.

#### 핵심 질문:

1. 주 사용자는 누구인가? (예: 개발자, 마케터, CEO, 운영팀)
2. 사용자가 가장 궁금해하는 정보는 무엇인가?

- 팁: 가상의 사용자 '페르소나'를 설정하면 좋습니다. "3년 차 퍼포먼스 마케터 김대리는 매일 아침 광고 채널별 효율과 예산 소진 현황을 가장 먼저 확인하고 싶어 한다."와 같이 구체적으로 설정하면 필요한 정보를 정의하기 쉽습니다.

## 3단계: 핵심 지표(KPI) 선정 (Selecting Key Metrics) 🔑

정의된 목표와 사용자에 맞춰 대시보드에 표시할 **가장 중요한 데이터(핵심 성과 지표, KPI)**를 선정합니다. 모든 데이터를 보여주는 것이 아니라, 목표 달성에 필수적인 정보만 선별하는 것이 중요합니다.

#### 지표의 종류:

1. 결과 지표 (Lagging Indicators): 이미 발생한 결과를 보여주는 지표 (예: 일일 총매출, 가입자 수)
2. 과정 지표 (Leading Indicators): 결과에 영향을 미치는 과정을 보여주는 지표 (예: 페이지 조회수, 장바구니 담은 횟수, 서버 응답 시간)

- 팁: "이 지표가 없으면 목표 달성 여부를 판단할 수 있는가?"라는 질문을 통해 핵심 지표를 걸러낼 수 있습니다. 5~7개 내외의 핵심 지표로 시작하는 것이 좋습니다.

## 4단계: 정보 구조 설계 (Information Architecture) ιε

선정된 지표들을 어떤 구조와 우선순위로 보여줄지 설계합니다. 사용자의 시선 흐름과 정보의 중요도를 고려하여 정보를 논리적으로 그룹화하고 배치합니다.

#### 일반적인 구조 (피라미드 구조):

1. 가장 상단 (Level 1): 가장 중요하고 요약된 핵심 지표 (KPI)를 크게 표시. (예: 현재 접속자 수, 실시간 매출액)
2. 중간 (Level 2): KPI의 추세나 패턴, 비교 분석 데이터 (예: 시간대별 매출 추이 그래프, 채널별 유입량 비교 차트)
3. 하단 또는 상세 페이지 (Level 3): 가장 구체적이고 세부적인 원본 데이터 (Raw Data) (예: 문제 발생 로그 리스트, 개별 주문 상세 내역 테이블)

- 팁: 사용자가 '한눈에 개요 파악 → 추세 및 원인 분석 → 상세 데이터 확인'의 흐름으로 자연스럽게 탐색(Drill-down)할 수 있도록 구조를 설계하는 것이 중요합니다.

## 5단계: 데이터 시각화 방법 결정 (Data Visualization) 📊

각 데이터의 특성과 전달하려는 메시지에 가장 적합한 차트와 그래프 유형을 선택합니다. 좋은 시각화는 데이터를 빠르고 직관적으로 이해시키는 핵심 요소입니다.

#### 차트 유형별 용도:

1. 라인 차트 (Line Chart): 시간 흐름에 따른 데이터 변화(추세)를 보여줄 때 (예: 시간대별 트래픽 변화)
2. 바 차트 (Bar Chart): 항목 간의 수량이나 크기를 비교할 때 (예: 상품별 판매량 비교)
3. 파이/도넛 차트 (Pie/Donut Chart): 전체에서 각 항목이 차지하는 비율을 보여줄 때 (단, 항목이 5~6개 이하일 때 효과적)
4. 숫자 & 게이지 (Number & Gauge): 가장 중요한 단일 수치(KPI)를 강조할 때 (예: 목표 달성률)
5. 히트맵 (Heatmap): 데이터의 밀집도나 분포를 색상으로 표현할 때 (예: 웹사이트 내 사용자가 많이 클릭하는 영역)
6. 테이블 (Table): 여러 항목의 정확한 수치를 상세하게 비교하며 봐야 할 때 (예: 로그 데이터 목록)

## 6단계: 레이아웃 및 UI/UX 디자인 (Layout & UI/UX Design)

지금까지 설계한 내용을 바탕으로 실제 화면의 레이아웃을 구성합니다. 사용자가 정보를 편안하고 효율적으로 인지할 수 있도록 디자인 원칙을 적용합니다.

#### 핵심 고려사항:

1. 시선 흐름: 사용자는 보통 왼쪽 상단에서 오른쪽 하단으로(Z 또는 F 형태) 시선을 이동합니다. 가장 중요한 정보는 왼쪽 상단에 배치하세요.
2. 그룹화: 연관성 있는 정보들은 시각적으로 가깝게 묶어서 배치합니다. (예: '매출 관련 지표' 그룹, '사용자 트래픽 관련 지표' 그룹)
3. 여백 활용: 충분한 여백은 각 요소를 구분하고 가독성을 높여줍니다.
4. 일관성: 색상, 폰트, 아이콘 등의 디자인 요소를 일관되게 사용하여 혼란을 줄입니다.
5. 인터랙션: 사용자가 데이터를 더 깊이 탐색할 수 있도록 필터링(날짜, 카테고리 등), 정렬, 드릴다운(클릭 시 상세 정보 표시) 기능을 제공합니다.

## 7단계: 프로토타이핑 및 개선 (Prototyping & Iteration) 🔄

처음부터 완벽한 대시보드를 만들기는 어렵습니다. 피그마(Figma), 스케치(Sketch) 같은 툴을 이용해 간단한 프로토타입(시제품)을 만들고 실제 사용자에게 테스트하며 피드백을 받아 개선하는 과정을 반복해야 합니다.

#### 프로세스:

1. 와이어프레임/목업 제작: 기능과 구조에 집중한 간단한 화면 설계
2. 사용자 테스트: 설계안을 사용자에게 보여주고 직접 사용하게 하며 의견 청취
3. 피드백 반영 및 수정: 테스트를 통해 발견된 문제점이나 개선사항을 설계에 반영
4. 개발 및 실제 데이터 연동 후 2차 테스트
